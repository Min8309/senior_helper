# 개발 및 보안 설정

## 실행·검증

Node 22.12 이상을 사용합니다. `npm ci`, `npm run dev`, `npm run build`로 설치·실행·빌드합니다. npm과 pnpm 잠금 파일 모두 갱신했습니다. pnpm 사용 시 `pnpm install --frozen-lockfile`도 가능합니다.

- 타입 검사: `npm run typecheck`
- 회귀 검사: `npm test` (브라우저 기능 검사 + PostgreSQL 기반 접근 정책 검사)
- 최초 브라우저 설치: `npx playwright install chromium`
- 시스템 Chromium을 사용할 경우: `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm test`

브라우저 테스트는 8445·8446 포트를 사용하고 Supabase 응답을 모킹합니다. 개인정보나 실제 API 키를 테스트에 사용하지 않습니다. SQL 검사는 PGlite의 PostgreSQL 엔진에서 인증·스토리지 스키마를 구성해 사용자 간 접근 차단, 공개 접근 차단, SQL 재실행을 검증합니다. 실제 Supabase 인프라의 검증을 대체하지 않습니다.

## Supabase 적용

1. 기존 DB를 백업한 후 Supabase SQL Editor에서 `supabase_schema.sql`을 실행합니다. 신규 설치와 기존 공개 정책 교체 모두 지원하며 트랜잭션으로 적용됩니다. `memory-audio` 버킷은 비공개로 전환됩니다.
2. Authentication 설정에서 Anonymous Sign-ins를 활성화합니다. 기존 로그인 세션이 있으면 그대로 사용하며, 세션이 없으면 익명 인증으로 서버가 발급한 사용자 UUID를 사용합니다. 인증 실패 시 로컬에 저장하고 클라우드 동기화 대기로 표시합니다.
3. 로컬 `.env.local` 또는 배포 설정에 `VITE_SUPABASE_URL`, 브라우저용 `VITE_SUPABASE_ANON_KEY`를 설정하고 개발 서버/빌드를 다시 시작합니다. 서비스 역할 키는 클라이언트에 넣지 않습니다.
4. 운영 프로젝트에 별도로 만든 RLS 정책이 있다면 확인합니다. PostgreSQL의 허용 정책은 OR로 결합되므로, 추가 공개 정책이 남아 있으면 소유자 정책만으로 차단할 수 없습니다. 이 SQL은 저장소에 있던 공개 정책과 이 프로젝트의 소유자 정책만 교체합니다.

이전 `user_...` 형식 사용자 ID로 원격 저장된 데이터는 새 인증 UUID와 자동 연결하지 않습니다. 검증된 소유자 매핑 없이 접근을 허용하면 다른 사람의 기록이 노출될 수 있습니다. 기존 원격 기록·음성은 관리자가 소유자를 확인한 후 사용자 ID와 버킷 경로를 이전해야 합니다. 로컬 기억은 보존하고, 중복 ID를 고유 ID로 이전합니다. 기존 로컬 저장소도 덮어쓰지 않고 남겨둡니다.

익명 인증은 같은 브라우저의 세션을 유지하는 방식입니다. 여러 기기에서 같은 계정을 쓰거나 세션을 잃었을 때 복구하려면 영구 계정 연결 기능이 추가로 필요합니다. 브라우저 저장소를 지우면 로컬 기록과 익명 세션을 잃을 수 있습니다.

## 기억 저장·삭제

새 기록의 ID는 UUID이고 로컬·원격에서 동일합니다. 로컬 저장 실패는 사용자에게 표시하며, 원격 실패는 동기화 대기 상태로 보관합니다. 다음 저장·조회·수정 요청이나 기억 화면에서 네트워크가 복구될 때 재시도합니다. 원격 조회 결과를 합칠 때 미동기화 로컬 기록을 보존합니다.

삭제는 로컬 목록에서 제거하는 동시에 삭제 대기 기록을 남깁니다. 클라우드 연결 후 음성 파일을 먼저 삭제하고 DB 기록을 삭제합니다. 실패하면 경로를 보관해 재시도하며 삭제된 기억을 다시 표시하지 않습니다. 오프라인 삭제는 클라우드에서 즉시 완료됐다는 의미가 아닙니다. 음성 재생은 5분 만료 서명 URL을 사용하고, 다시 듣기를 누를 때 갱신합니다.

## 사진 분석·대화

`VITE_N8N_ANALYZE_WEBHOOK`에는 기존 분석 서버의 주소를 설정합니다. 백엔드는 토큰을 보관하고 CORS 및 아래 응답 형식을 지원해야 합니다. 모델 키를 `VITE_` 변수로 노출하지 않습니다.

```json
{
  "success": true,
  "device_name": "확인된 기기 이름",
  "instructions": ["실제로 확인한 사용법 (1~3개)"],
  "needs_new_photo": false
}
```

서버 미연결·실패·잘못된 응답에서는 성공이나 신뢰도를 꾸며내지 않고 안내를 중단합니다. 재촬영이 필요한 경우 `success: false`, `needs_new_photo: true`, `error_guide`를 반환합니다. 실제 기기 식별과 안내 정확성은 별도 운영 검증이 필요합니다.

일반 대화는 미리 준비된 응답이며 화면에도 이를 표시합니다. 날씨 질문은 홈페이지에서 가져온 최신 날씨 캐시로 답변하고, 자료가 없거나 오래됐으면 재조회 안내를 제공합니다.


## 현재 날씨

Open-Meteo Forecast API(`https://api.open-meteo.com/v1/forecast`)에서 기온, 체감온도, 상대습도, WMO 날씨 코드, 낮/밤 여부를 가져옵니다. 기본 지역은 서울이며 화면에 기준 지역을 표시합니다. 지역 선택은 17개 주요 도시를 지원합니다. `내 위치`를 누를 때만 브라우저 위치 권한을 요청하고, 약 1km 단위(소수점 둘째 자리)로 반올림한 좌표를 날씨 서비스에 보냅니다. 선택 지역과 마지막 자료는 기기의 localStorage에 보관합니다.

화면이 열릴 때, 10분 간격, 네트워크 복구, 화면 복귀 시 갱신합니다. 요청은 8초 후 중단하며 지역 전환 시 이전 요청을 취소합니다. 실패하면 마지막 값을 유지하되 이전 자료와 오류를 표시합니다. 자료 시각 또는 가져온 시각이 30분을 넘으면 최신 정보가 아니라고 표시하며 대화에서 현재 날씨처럼 사용하지 않습니다. 날짜와 시각은 사용자의 현지 시간대로 표시합니다.

현재 자료는 Open-Meteo의 약 15분 간격 기상 모델 자료이며 현장 센서의 초 단위 관측값은 아닙니다. 공개 API는 API 키 없이 연결되며, 상용 배포나 대규모 사용 전 [Open-Meteo 이용 조건](https://open-meteo.com/en/terms)을 확인하고 적절한 API 요금제를 사용해야 합니다. 출처 링크는 날씨 카드에 표시합니다.

클라우드 네트워크 제한을 사용하는 경우 `api.open-meteo.com`을 허용 도메인에 추가합니다. 브라우저가 직접 HTTPS로 요청하므로 별도 서버·비밀 키는 필요 없습니다. 위치 기능은 HTTPS 또는 localhost에서 지원되며, 권한 거절 시 지역 선택을 사용할 수 있습니다. 날씨 테스트는 API·위치 응답을 모킹하여 성공, 오류, 오래된 자료, 지역 변경 및 접근 권한 거절을 검증합니다.
